# 轻迹 · 跑步模拟

Windows 上运行的本地 iPhone 定位工作台，通过 USB 连接手机，在浏览器里选点、规划路线并模拟移动。

## 功能

- 地图选点与单点虚拟定位，持续保持当前位置。
- 直线路线、平滑曲线，以及可移动、调整长宽和旋转的操场模板。
- 路线保存、加载、撤销／重做、闭环和无限循环。
- 配速设置、每圈随机浮动、平滑变速与小幅连续轨迹偏移。
- 暂停休息、结束后保持位置，以及恢复真实定位。
- iPhone 快捷指令通过局域网回传当前位置，支持扫描回传地址二维码。
- 可选的本地操场校准；校准配置与路线均只保存在本机。

## 安装与启动

需要 Windows、Python 3.10 及以上、Apple 设备驱动，以及开启开发者模式并信任电脑的 iPhone。当前开发环境使用 Python 3.15；具体 iOS 版本能否连接仍需实机确认。

在项目目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

然后双击 `start.cmd`，默认浏览器会打开 [本机控制页面](http://127.0.0.1:8765)。启动、打开页面和检测设备不会设置手机位置。

首次使用：USB 连接并信任电脑 → 检测设备 → 准备设备 → 地图选点或规划路线 → 设置定位或开始跑步。

结束时点击网页右上角“退出程序”。正在模拟时会先尝试恢复定位；恢复失败会保留程序供重试。单独关闭网页不会停止后台任务。保持电脑运行和 USB 连接，恢复效果请在手机地图确认。

## 本地数据

`data/` 保存路线、私有校准和生成的网页；`.local/` 保存日志、调试截图和测试缓存。这两个目录及 `.venv/`、`node_modules/` 均已加入 `.gitignore`，不应上传 GitHub。

本机已有的路线与校准已保留。新克隆的项目没有个人校准时自动使用原坐标。代码和测试不包含个人位置、手机标识或配对地址。

## 新建偏移校准配置

配置文件放在项目目录下的 `data/calibration.json`。没有配置时，程序自动使用原坐标；它不会根据地点自动生成校准参数。

首次创建可以复制 [配置示例](config/calibration.example.json)。在项目目录运行以下命令；如果已有配置，该命令不会覆盖它：

```powershell
New-Item -ItemType Directory -Path data -Force | Out-Null
if (-not (Test-Path -LiteralPath data/calibration.json)) {
    Copy-Item -LiteralPath config/calibration.example.json -Destination data/calibration.json
}
```

用文本编辑器打开 `data/calibration.json`，按自己的校准结果填写。文件使用 JSON 格式，以下是**占位示例，不是实际校准值**：

```json
{
  "profiles": [
    {
      "name": "地点 A",
      "enabled": true,
      "origin_lat_lng": [0, 0],
      "axis_scales": [1, 1],
      "shift_east_north_m": [0, 0],
      "radius_m": 250
    },
    {
      "name": "地点 B",
      "enabled": false,
      "origin_lat_lng": [0, 1],
      "axis_scales": [1, 1],
      "shift_east_north_m": [0, 0],
      "radius_m": 250
    }
  ]
}
```

| 字段 | 顺序与含义 |
| --- | --- |
| `name` | 本组修正的名称，必须非空且各组名称不同；网页会显示实际采用的名称。 |
| `enabled` | `true` 启用本组，`false` 关闭本组。必须是小写布尔值，不要加引号。 |
| `origin_lat_lng` | `[中心纬度, 中心经度]`，缩放与适用范围的中心，使用 WGS84 坐标。 |
| `axis_scales` | `[东西缩放比例, 南北缩放比例]`，均须大于零。`1` 不缩放，`0.9` 缩小 10%，`1.1` 放大 10%。 |
| `shift_east_north_m` | `[向东平移米数, 向北平移米数]`。正数为东、北，负数为西、南；在缩放之后平移。 |
| `radius_m` | 适用半径，单位米，须大于零。只有能覆盖单点或整条路线的组才参与选择。 |

例如，相对中心向东 100 米的点，东西比例设为 `0.9`、向东平移设为 `2`，修正后位于中心以东 `100 × 0.9 + 2 = 92` 米处。缩放处理的是相对中心的距离，不是把经纬度数值直接相乘。

每一组 `{ ... }` 代表一个修正区域。增加地点时，复制 `profiles` 数组中的一组，修改名称、开关和参数；组与组之间用逗号分隔。示例中的地点 A 已开启、地点 B 已关闭，两个地点的参数都是占位值。

**修改并保存文件后，需要退出程序并重新打开。** 程序只在启动时读取文件，中途修改不会改变当前任务或新任务的配置。网页“启用修正”是总开关；总开关关闭时，不使用任何组。

选择规则：先排除 `enabled: false` 的组，再寻找能覆盖整个单点或整条路线的组；若有多组符合，采用距单点／路线起点最近的一组，距离相同时采用文件中靠前的一组。一次任务只应用一组，不叠加、不在路线中途切换。没有符合的组时使用原坐标。

网页会显示启动时读取、启用的组数和名称；设置定位或开始跑步后显示实际采用的组名。配置格式错误时会提示错误，修复后重启。旧版单组配置仍可读取，默认启用。


网页选点与保存的路线保留原坐标，发送手机时才补偿。该配置仅用于对应地点的局部对齐，不应直接套用到其他地点；建议先用几个固定点验证。JSON 文件内不要加注释或末尾多余的逗号。

个人配置已被 Git 忽略，不随源码上传。更详细的说明见 [本地校准配置](docs/calibration.md)。

## 检查

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -t . -q
node tests/test_route_geometry.mjs
```

自动化测试使用模拟设备；浏览器检查方法见开发文档。网页显示的是程序模拟进度与目标位置，不是手机 GPS 的实时回读或运动软件确认的记录。
